## 헙 커밋 규칙

### 작업 타입

| 작업 타입 | 작업내용 |
| --- | --- |
| `Feat` | 새로운 기능 추가 (새로운 구현) |
| `Fix` | 코드 수정, 버그 수정 |
| `Refactor` | 코드 리팩토링 |
| `Rename` | 파일 또는 폴더 명을 수정, 파일 옮김/정리 |
| `Remove` | 기능/파일을 삭제 |
| `Test` | 테스트 코드를 작성 |
| `Chore` | (코드의 수정 없이) 그 외 기타 수정 |
| `Gitfix` | gitignore 수정 |
| `Comment` | 필요한 주석 추가 및 변경 |
| `Docs` | 문서 추가, 수정, 삭제 |
| `!HOTFIX` | 급하게 치명적인 버그를 고쳐야 하는 경우 |

### Body

<aside>
💡

Header에서 표현할 수 없는 **상세한 내용**을 적는다.

Header에서 충분히 표현할 수 있다면 **생략 가능**하다.

</aside>

- 72이내로 작성한다.
- 최대한 상세히 작성한다. (코드 변경의 이유를 명확히 작성할수록 좋다)
- 어떻게 변경했는지보다 무엇을, 왜 변경했는지 작성한다.

### Footer

<aside>
💡

바닥글로 어떤 이슈에서 왔는지 같은 **참조 정보들을 추가**하는 용도로 사용한다.

예를 들어 특정 이슈를 참조하려면 Issues #1234 와 같이 작성하면 된다.

Footer는 **생략 가능**하다.

</aside>

- issue tracker ID 명시하고 싶은 경우에 작성한다.
- 유형: #이슈 번호 형식으로 작성한다.
- 여러 개의 이슈번호는 쉼표(,)로 구분한다.

### 예시
```jsx
Add: Initialize GitHub Actions workflow

PR 생성 시 빌드 및 테스트가 실행되도록
GitHub Actions 워크플로우 파일 신규 추가

#5
```
